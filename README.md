# Anivox Desktop

Настольная оболочка для [anivox.fun](https://anivox.fun/) на Tauri v2 для Windows и Linux.

## Возможности

- Независимая панель навигации: назад, вперёд, обновление страницы.
- Один экземпляр приложения: повторный запуск показывает существующее окно, включая скрытое в трей.
- Открытие текущего видео в MPV с передачей позиции, заголовка, субтитров и HTTP-заголовков.
- Discord Rich Presence для встроенного плеера и MPV: аниме, серия, постер и оставшееся время.
- Shikimori поверх сайта; закрытие не перезагружает Anivox.
- Проверка соединения: определяет, что тормозит видео — ваш интернет или видео-сервер.
- Просмотр изменений перед установкой обновления, прогресс загрузки и перезапуск.

## Установка и зависимости

Готовые сборки находятся в [GitHub Releases](https://github.com/AXELL2022/Anivox-Wraper/releases).

**Windows:** требуется WebView2 Runtime. Для внешнего воспроизведения — MPV.

**Linux:** требуется GTK 3 и WebKitGTK 4.1. MPV устанавливается отдельно. Доступны AppImage, deb и пакет Arch Linux из процесса сборки.

## MPV и журналы

Нажмите ⚙ на панели. Выберите исполняемый файл MPV через «Обзор…» или укажите абсолютный путь, затем нажмите «Сохранить». Пустой путь означает поиск `mpv` в PATH. Сброс пути применяется после сохранения. Настройка действует при следующем открытии видео; существующий MPV не закрывается.

Настройки хранятся в `settings.json` в каталоге конфигурации Anivox. Журналы создаются отдельно для каждого запуска в `logs` внутри локального каталога данных приложения. Полный путь к журналам отображается в настройках.

| Система | Настройки | Журналы |
| --- | --- | --- |
| Windows | `%APPDATA%\com.yasin.anivox\settings.json` | `%LOCALAPPDATA%\com.yasin.anivox\logs\` |
| Linux | `$XDG_CONFIG_HOME/com.yasin.anivox/settings.json` | `$XDG_DATA_HOME/com.yasin.anivox/logs/` |

На Linux при незаданных XDG-переменных используются `~/.config` и `~/.local/share` соответственно.

Внешний плеер запускается кнопкой MPV или клавишей M / Ь. При ошибке запуска встроенное видео продолжает воспроизводиться. Discord получает паузу, оставшееся время и скорость внешнего MPV через локальный JSON IPC. Метаданные серии фиксируются при запуске; открытие другой страницы не меняет карточку текущего MPV.

При повторном запуске серии в MPV Anivox предлагает продолжить с сохранённой позиции, начать сначала или отменить запуск. Прогресс привязан к аниме, серии и озвучке; хранится локально в `playback-history.json` рядом с настройками. Первые 10 секунд и последние 5% / 30 секунд не предлагаются для продолжения. Историю можно очистить в настройках.

Режим «Продолжать воспроизведение на сайте при просмотре в MPV» выключен по умолчанию. После подтверждения готовности MPV встроенный плеер работает без звука на минимальном доступном качестве и следует его паузе, перемотке и скорости. При закрытии MPV прежние качество и звук восстанавливаются, встроенный плеер остаётся на паузе. Два плеера увеличивают нагрузку и расход трафика; опыт и часы начисляет сайт, приложение не отправляет искусственные события просмотра.

Закрытие основного окна скрывает его в трей; для завершения выберите «Выход» в меню трея.

## Проверка соединения

Если видео подвисает, нажмите иконку Wi‑Fi на верхней панели (слева от ⚙) и держите панель открытой во время просмотра. Она обновляется каждую секунду и показывает две строки:

- **Скорость вашего интернета** — разовое измерение скачиванием тестового файла с `speed.cloudflare.com` (кнопка «Проверить снова» повторяет его).
- **Загрузка видео** — текущая скорость скачивания видео-сегментов (`.ts`, `.m4s`, `.mp4`) с сервера плеера за последние 6 секунд; сегмент, не получивший ни байта 5 секунд, отображается как «Завис».

Скорость ниже 10 Мбит/с отображается красным. Итоговый вывод: «Проблема с вашим интернетом» (медленный или недоступный канал), «Тормозит видео-сервер, а не ваш интернет» (канал быстрый, а сегменты приходят медленно или не приходят — подождите, выберите другую озвучку или включите VPN) либо «Всё в порядке». Пока видео не включено, панель показывает только скорость интернета. Монитор сегментов только наблюдает за запросами сайта и ничего не меняет и не отправляет наружу.
## Разработка

Нужны Bun, актуальный stable Rust и системные зависимости Tauri v2. На Windows также нужны MSVC Build Tools и доступный `rust-lld.exe`, выбранный в `.cargo/config.toml`. Linux-зависимости перечислены в `.github/workflows/build.yml`.

```sh
bun install --frozen-lockfile
bun run dev
bun run build
bun run build:arch
bun run install:arch
bun run tauri info
```

Сборки находятся в `src-tauri/target/release/`; установочные пакеты — в подкаталогах `bundle/`.

## Проверки

```sh
node --test tests/*.test.mjs
cargo check --locked --manifest-path src-tauri/Cargo.toml
cargo test --locked --manifest-path src-tauri/Cargo.toml
cargo fmt --manifest-path src-tauri/Cargo.toml -- --check
```

После release-сборки на Windows, закрыв остальные экземпляры Anivox:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tests/windows_taskbar_icon.ps1 -Exe src-tauri/target/release/anivox.exe
powershell -NoProfile -ExecutionPolicy Bypass -File tests/windows_single_instance.ps1 -Exe src-tauri/target/release/anivox.exe
```

В self-hosted CI для этих проверок отдельно собирается EXE с идентификатором `com.yasin.anivox.ci-native` и собственным профилем. Он не конфликтует с запущенным пользовательским Anivox. Исходный EXE восстанавливается с проверкой SHA-256; установщики и опубликованные артефакты сохраняют обычный идентификатор.

Скрипты завершают только свои тестовые экземпляры. Проверки Discord, MPV и удалённого сайта требуют соответствующих внешних программ и доступа к сервисам.

## Обновления и выпуск

Значок обновления открывает окно с изменениями. «Позже» ничего не устанавливает; «Установить» повторно проверяет выбранную версию. Если вышла другая версия, приложение покажет её описание и запросит новое подтверждение. Для Linux вне AppImage открывается страница ручной установки.

CI запускает JS- и Rust-тесты, проверяет форматирование и компиляцию на Windows/Linux. Windows использует runner с метками `self-hosted, Windows, X64` и проверяет значки и single-instance; Linux собирается на GitHub-hosted Ubuntu. На общем рабочем столе Windows CI использует `-SkipForegroundCheck`: проверяет завершение второго процесса, видимость и восстановление первого окна, но не требует активного фокуса, который Windows может запретить фоновому процессу. Локальный запуск теста без этого флага сохраняет строгую проверку фокуса. Каталог `actions-runner/` исключён из Git. Для тега `vX.Y.Z` описание берётся из секции `## [X.Y.Z]` в `CHANGELOG.md`. Один `release-notes.md` используется и для GitHub-релиза, и для поля `notes` в `latest.json`. Отсутствующая или пустая секция останавливает выпуск.

Self-hosted Windows хранит Bun нужной версии и полные Cargo target-каталоги в `RUNNER_TOOL_CACHE/anivox`, вне очищаемого checkout. Основная сборка и EXE с тестовым идентификатором используют отдельные target-каталоги, чтобы не сбрасывать результаты друг друга. Windows не загружает и не очищает облачный Rust Cache; Linux продолжает его использовать. Cargo получает число задач по доступным логическим CPU; отладочные символы dev/test отключены только в CI. Перед выпуском удаляются лишь старые установщики, зависимости сохраняются. Первый запуск заполняет локальный кэш, последующие используют готовые результаты.

## Исходники

- `src-tauri/src/lib.rs` — окна, IPC, Discord, MPV, настройки и обновления.
- `src-tauri/scripts/` — общие и платформенные инъекции удалённого webview.
- `ui/` — локальная панель, Shikimori, настройки и описание обновления.
- `tests/` — JavaScript и Windows-интеграционные проверки; Rust-тесты расположены рядом с `lib.rs`.
- `scripts/generate-updater-manifest.mjs` — извлечение changelog и создание манифеста.

Подробности архитектуры — в `INIT.md`, правила разработки — в `AGENTS.md`, история — в `CHANGELOG.md`.
