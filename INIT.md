# Anivox Desktop — текущая архитектура

## Назначение и сборка

Tauri v2, Rust 2021, Windows/WebView2 и Linux/WebKitGTK 4.1. Идентификатор приложения — `com.yasin.anivox`, текущая версия — `0.3.1`. Целевой сайт — `https://anivox.fun/`. Пакетный менеджер JavaScript — Bun. Команды сборки и тестов приведены в README и AGENTS.

`src-tauri/src/main.rs` вызывает `anivox_lib::run()` и сохраняет подавление консоли Windows release. Backend остаётся в `src-tauri/src/lib.rs`; frontendDist в tauri.conf.json указывает на `../ui`. Корневой шаблонный `src/` удалён.

## Окна и внедряемый код

- Windows: нативное окно `main` с child webviews `toolbar` (локальная панель) и `content` (Anivox).
- Linux: окно/webview `content`; панель из `ui/toolbar-fragment.html`, CSS и JS внедряется в удалённую страницу через Shadow DOM.
- Скрипты `src-tauri/scripts/inject-common.js`, `inject-windows.js`, `inject-linux.js` собираются через include_str!/concat!. Windows сохраняет флаги WebView2/NVIDIA; Linux — текущие GTK/WebKit обходы проблем движка.
- Shikimori создаётся лениво в `shikimori` с локальным `shikimori-overlay`. Закрытие уничтожает оба webview; повторное открытие загружает домашнюю страницу Shikimori.
- Локальные окна `settings` и `update-review` открываются независимо от сайта. Повторное открытие фокусирует существующее окно. Их закрытие не скрывает главное окно, не отключает VPN и не завершает Anivox.
- Все Windows webviews используют совместимые browser arguments для общего WebView2-профиля.

Single Instance плагин регистрируется первым. Второй процесс показывает, восстанавливает и фокусирует существующее основное окно. Крестик основного окна скрывает его в трей, «Выход» завершает приложение.

## Системный WireGuard VPN

Конфигурация `ANIVOX-UA-48.conf` встраивается при сборке через include_str!. Туннель называется `ANIVOX-UA-48`.

Windows использует `wireguard.exe` и tunnel service; Linux — NetworkManager/nmcli с fallback на wg-quick. VPN меняет системные маршруты/DNS. Активного SmartProxy, proxy.rs, встроенного wireproxy или настройки socks5-прокси в текущей архитектуре нет; старый wireproxy.exe удалён.

Явное переключение Windows при access denied повторяет только операцию WireGuard с UAC. Отмена UAC возвращается как ошибка панели. При запуске и штатном выходе выполняется best-effort отключение туннеля без повышения прав. Закрытие окна в трей не является выходом.

## MPV и настройки

`open_in_mpv` читает PlayerSettings из settings.json в Tauri app_config_dir. Путь выбирается в локальном окне настроек через системный диалог; пустое значение означает mpv в PATH. Явный путь проверяется и не заменяется запасным EXE при ошибке.

Настройки сохраняются атомарно через временный файл в том же каталоге и замену назначения. Повреждённый файл при чтении не перезаписывается. Параллельные чтения/сохранения сериализуются.

Журналы MPV создаются в app_local_data_dir/logs отдельным файлом на запуск. Каталог установленного EXE и F:\Mpv не используются. Параметры передаются напрямую через std::process::Command: URL, заголовок, стартовая позиция, субтитры, HTTP-заголовки и параметры качества. После готовности MPV встроенное видео ставится на паузу либо зеркалит реальное воспроизведение без звука на минимальном качестве, если включён mirrorEmbedded. Наблюдаются pause, time-pos, duration, speed, paused-for-cache и eof-reached; локальный named pipe/Unix socket уникален для сессии. Прогресс сохраняется атомарно в playback-history.json по ключу anime:episode:translation. Anivox не завершает запущенный MPV при собственном выходе.

## Discord

Существующий DiscordPresence и DiscordState обслуживают встроенный плеер через set_discord_rpc. Инъекция собирает метаданные и состояние видео; backend обновляет Discord Rich Presence с восстановлением соединения. Активная сессия внешнего MPV имеет приоритет над встроенным плеером. Метаданные замораживаются при handoff, а состояние и таймер берутся из MPV IPC. При завершении или потере IPC возвращается последнее состояние встроенного плеера.

## Обновления

check_update возвращает версию и описание. Панель вызывает open_update_review; локальное окно показывает changelog как текст. install_update доступен только update-review, принимает expectedVersion и повторно проверяет версию перед скачиванием. При расхождении возвращается update_changed с новым описанием, требующим нового подтверждения. Параллельная установка блокируется.

События update-started/update-progress/update-finished/update-idle управляют состоянием панели и окна обновления. Ошибки позволяют повторить попытку. Linux вне AppImage после подтверждения открывает страницу ручного обновления; остальные поддерживаемые сборки используют существующий Tauri updater.

CI сначала извлекает notes для точной версии из CHANGELOG в release-notes.md, затем создаёт latest.json с тем же текстом и передаёт файл в GitHub Release. Пустая или отсутствующая секция — ошибка выпуска.

## Разрешения и проверки

Каждая новая команда регистрируется в generate_handler!, описывается в permissions/*.toml и включается в подходящие capabilities. Чтение/изменение настроек и выбор EXE доступны только локальному settings; установка — только локальному update-review. Дополнительно проверяются метка webview и локальный URL. Их навигация на удалённые сайты блокируется.

Anivox content имеет origin-scoped права для https://anivox.fun/*. На Linux ему разрешено открывать локальные настройки и окно описания обновления, но не менять путь EXE или устанавливать обновление напрямую. Shikimori может только закрыть свой overlay; внешние OAuth-провайдеры не получают IPC.

CI: JS-тесты и cargo test на Windows/Linux, затем сборка. После Windows-сборки последовательно проверяются ICON_SMALL/ICON_BIG и single-instance/восстановление окна. Выпуск зависит от успешного завершения обеих платформ. Для локальной проверки запускают cargo check, cargo test, cargo fmt --check и node --test tests/*.test.mjs; реальные внешние интеграции и визуальная проверка учитываются отдельно.
