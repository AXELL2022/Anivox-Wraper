# Проверка MPV, обновлений и выпуска — 2026-10-18

## Исправление запуска именно через run.bat

Точный сценарий воспроизведён командой `cmd.exe /c run.bat`, а не отдельным
cargo build или запуском EXE. Tauri CLI запускает встроенный dev-сервер и
устанавливает build.devUrl в `http://127.0.0.1:1430/`. Прежний фильтр
локальных окон принимал только tauri://localhost и http(s)://tauri.localhost.
Он блокировал dev-страницу; после добавления ожидания загрузки такое окно
оставалось скрытым. Это объясняет различие run.bat и release.

Фильтр навигации, завершения загрузки и проверки вызывающего локального окна
теперь используют один predicate с configured devUrl. Только в debug
принимается точный origin настроенного HTTP(S) loopback dev-сервера;
другие порты/схемы/хосты, URL с учётными данными и внешние devUrl запрещены.
Release по-прежнему принимает только встроенные application origins.

Регрессионный debug-тест сначала упал на configured dev page must load,
после исправления полный Rust-набор 16/16 прошёл. JS 75/75, fmt passed.
Отдельный release-тест release_local_windows_do_not_trust_dev_origins прошёл.

В настоящем запуске run.bat через кнопку открыта страница
http://127.0.0.1:1430/settings.html: визуально проверены поля и кнопки,
сохранённый путь MPV и каталог журналов. Чтение настроек через IPC прошло.
Временный вывод configured dev URL из исходников удалён.

## Повторная проверка после сообщения о чёрном окне и MPV

Пользователь сообщил о чёрном окне настроек и неработающем MPV. В этом
запуске проверены и debug, и release. После полного перезапуска исходная
release-сборка также показала содержимое настроек; устойчивый исходный сбой
не воспроизведён. Диагностика показала начальный about:blank перед загрузкой
локального HTML и успешные ответы 200 для settings.html/CSS/JS.

Чтобы не показывать пустой начальный документ, вспомогательные окна теперь
создаются скрытыми и показываются после PageLoadEvent::Finished локальной
страницы. Повторное нажатие во время загрузки не раскрывает about:blank.
Временные трассировка и автоматическое открытие окна удалены из исходников.

Проверено обычное открытие настроек кнопкой в окончательной release-сборке:
поле пути, кнопки и каталог журналов отображаются. Сохранение проверено
через настоящий интерфейс; выбран существующий MPV на машине пользователя.
В PATH MPV отсутствует, поэтому пустая настройка не позволяла его запустить.
Выбор хранится в settings.json; жёсткая привязка в код не возвращалась.

Добавлена передача подробной ошибки запуска MPV в строку состояния панели.
Два регрессионных JS-теста сначала подтвердили отсутствие подробностей,
после изменения прошли. Полные наборы: 75 JS и 15 Rust, форматирование passed.
Окончательный release EXE пересобран в target/verified/release.

Из окончательной сборки реально передан эпизод Anivox в MPV; появилось окно
MPV с названием серии. Новый журнал в app_local_data_dir/logs подтвердил
Starting playback, VO и AO, без Failed to open/ошибки формата/открытия.
Таким образом, handoff, видео и звук проверены; старое ограничение ниже
о непроверенной передаче теперь относится только к предыдущему запуску.

## Принятые технические решения

1. Работа в текущем каталоге на отдельной ветке сохраняет существующие
   правки значков и single-instance. Цена: файловая система не изолирована
   от других инструментов, работающих в этом checkout.
2. Bash bookkeeping заменён файлом progress.md для PowerShell-окружения.
   Цена: прогресс учитывается вручную.
3. Смешанные файлы оставлены незакоммиченными, чтобы не включать чужие
   изменения в новые коммиты. Цена: границы задач не представлены коммитами.
4. Файловые Rust-тесты запускались вне песочницы после отказа tempfile.persist
   в виртуализированном temp. Неизменённые тесты вне песочницы проходят.
   Цена: поведение самой песочницы не является проверенным desktop-сценарием.
5. `.gitattributes` сохраняет исходное CRLF-хранение lib.rs: в HEAD этот файл
   содержит CRLF, а core.autocrlf=true без атрибута превращает diff в замену
   всего файла. Цена: для lib.rs сохраняется его существующий формат строк.
6. Финальный EXE собран отдельно после остановки UI пользователем. Цена:
   для запуска финальной версии нужно использовать указанный verified EXE,
   предварительно завершив старый экземпляр через меню трея.
