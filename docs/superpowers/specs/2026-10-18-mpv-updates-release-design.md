# Anivox: настройки MPV, обновления и проверки выпуска

Дата: 2026-10-18. Статус: согласовано пользователем после исключения интеграции MPV с Discord.

## Цель и границы

Выполнить четыре согласованных изменения: настраиваемый MPV без путей к
диску F:, changelog перед установкой, Rust и Windows-проверки в CI, очистка шаблона
и устаревших файлов и документов. Сохранить изменения single-instance и
значков, уже находящиеся в рабочем дереве. Версию приложения и публикацию
GitHub-релиза эта работа не меняет.

По решению пользователя интеграция MPV с Discord отложена. Текущее
отслеживание встроенного плеера для Discord остаётся без изменений.

## 1. Настройки и запуск MPV

- Добавить кнопку настроек в обе версии панели: Windows и Linux.
- Открывать отдельное локальное окно настроек. Повторное открытие
  фокусирует существующее окно. Закрытие уничтожает только это окно;
  Anivox и воспроизведение продолжают работать.
- Поле «Путь к MPV», кнопки «Обзор», «Сохранить» и сброс к поиску в PATH.
  Выбирается исполняемый файл MPV; поддержка других типов плееров не входит
  в задачу, поскольку параметры запуска предназначены для MPV.
- Пустое значение означает запуск `mpv` из PATH. Явный путь должен быть
  абсолютным и указывать на существующий файл. Неправильный путь даёт
  понятную ошибку; приложение не подменяет выбор пользователя другим EXE.
- Настройку хранить в `settings.json` в каталоге конфигурации приложения,
  определяемом Tauri. Сохранять через временный файл с заменой; применять
  только после успешного сохранения. Отсутствующий файл означает настройки
  по умолчанию; повреждённый файл не перезаписывать без явного сохранения.
- Журналы MPV хранить в `logs` внутри доступного для записи локального
  каталога данных Anivox, определяемого Tauri. Это папка приложения для
  пользовательских данных, а не каталог установленного EXE. Показать её
  путь в настройках. Для разных запусков использовать отдельные журналы.
- Сохранить передачу стартовой позиции, заголовка, субтитров, HTTP-заголовков
  и текущих параметров качества. Удалить зависимость от рабочего каталога
  `F:\Mpv`; не менять пользовательскую конфигурацию MPV.
- Ошибка запуска отображается в панели. Встроенное видео при неудачной
  передаче остаётся воспроизводимым; паузу закреплять после успешного запуска.

## 2. Описание обновления и установка

- Сначала извлекать секцию версии из CHANGELOG, затем использовать один
  файл описания для GitHub-релиза и поля `notes` в `latest.json`.
- Отсутствие секции версии в release-процессе считать ошибкой проверки;
  не выпускать манифест с текстом-заглушкой.
- Нажатие на значок обновления открывает локальное окно с номером версии,
  прокручиваемым текстом изменений и кнопками «Установить» / «Позже».
  Само открытие окна ничего не скачивает и не устанавливает.
- Показывать описание как текст, без исполнения HTML. Закрытие окна
  и «Позже» сохраняют возможность вернуться к обновлению.
- После подтверждения сохранить существующий прогресс, ошибки и перезапуск.
  Для Linux вне AppImage сохранить переход на страницу ручной установки.
- Перед установкой повторно проверить обновление; при смене версии показать
  новое описание и запросить подтверждение именно новой версии.

## 3. IPC приложения и размещение кода

Основная логика остаётся в `src-tauri/src/lib.rs`, соответствуя AGENTS.md.
Тесты Rust можно вынести в соседние тестовые модули. Новые локальные страницы
и их скрипты размещаются в `ui/`. Изменения удалённых media hooks — в
`inject-common.js`; платформенные настройки WebView2 и WebKit сохранить.

Для новых команд определить permission-файлы, регистрацию и capabilities.
Выбор EXE, сохранение настроек и установка из локального окна доступны
только предусмотренным локальным webview с проверкой вызывающего окна.
Shikimori и внешним страницам входа доступ не добавлять. Linux-панель
может открывать локальное окно, но не получает право записывать путь EXE.

## 4. CI, очистка и документация

- Добавить `cargo test --manifest-path src-tauri/Cargo.toml` в обе платформы
  после установки системных зависимостей и до упаковки приложения.
- После Windows-сборки запускать `tests/windows_taskbar_icon.ps1` на
  release-EXE. Сбой блокирует публикацию артефактов и релиза.
- Включить существующий тест single-instance в Windows-проверки, запускать
  последовательно с проверкой значка, чтобы процессы не мешали друг другу.
- Удалить отслеживаемые `src-tauri/binaries/wireproxy.exe` и корневой `src/`
  после проверки отсутствия ссылок из сборки. Историю Git не переписывать.
- README описывает назначение, Windows/Linux, зависимости, MPV, Discord,
  системный WireGuard, сборку, настройки, журналы и проверочные команды.
- INIT описывает текущие webview, инъекции, IPC и системный VPN; удалить
  утверждения об активных SmartProxy, proxy.rs и встроенном wireproxy.
- Исторические записи CHANGELOG сохранить как историю; новые изменения
  записать в раздел невыпущенных изменений. Согласовать AGENTS.md с
  удалением шаблона и заменой правил поиска MPV.

## Проверка и критерии готовности

1. Rust-тесты: сохранение/загрузка настроек, ошибки пути и аргументы MPV.
2. JS-тесты: успешная и неудачная передача видео; просмотр и отмена обновления;
   прогресс установки; changelog версии в сохранённом манифесте.
3. Windows-интеграция: release-EXE, значки, single-instance, настройки и
   воспроизведение через реальный MPV, если MPV доступен на машине.
4. Полные JS- и Rust-наборы, cargo check, проверка форматирования с отдельным
   учётом старых отличий. Проверить конечный diff на посторонние изменения.
5. CI проверить по структуре и командам. Успешный запуск GitHub Actions
   заявлять только при фактическом запуске; Linux отмечать отдельно,
   если проверить его в текущем окружении невозможно.

Готовность означает работающий код и проверенный Windows-EXE, актуальную
документацию и CI-конфигурацию. Создание публичного релиза не входит в задачу.
